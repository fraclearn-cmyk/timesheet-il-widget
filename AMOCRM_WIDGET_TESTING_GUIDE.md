## 📦 ПОДГОТОВКА ВИДЖЕТА

### Шаг 1: Обновить API URL в script.js

**⚠️ ВАЖНО: Замените `localhost:8000` на ваш реальный API URL**

Откройте файл `widget/script.js` и найдите строку 13:

```javascript
// Было:
apiBaseUrl: 'http://localhost:8000/api/v1',

// Должно быть:
apiBaseUrl: 'https://your-domain.com/api/v1',
// или для ngrok:
apiBaseUrl: 'https://abc123.ngrok.io/api/v1',
```

### Шаг 2: Обновить CSS URL в script.js

Найдите строку 145 в `widget/script.js`:

```javascript
// Было:
var cssUrl = 'https://example.com/widget/styles.css';

// Должно быть:
var cssUrl = 'https://your-domain.com/widget/styles.css';
```

**Примечание:** CSS файл должен быть доступен по публичному URL.

### Шаг 3: Обновить manifest.json (поддержка и логотипы)

Откройте `widget/manifest.json`:

```json
{
  "widget": {
    "name": "widget.timesheet_il",
    "description": "Табель учёта рабочего времени с отслеживанием активности",
    "short_description": "Учёт рабочего времени",
    "version": "1.0.0",
    "interface_version": 2,
    "init_once": false,
    "locale": ["ru", "en"],
    "installation": true,
    "support": {
      "link": "https://your-domain.com/support",  // ← Обновить
      "email": "support@your-company.com"          // ← Обновить
    }
  },
  "settings": {
    "login": "",
    "client_id": "",                               // ← Заполнить при OAuth
    "client_secret": "",                           // ← Заполнить при OAuth
    "redirect_uri": ""                             // ← Заполнить при OAuth
  }
}
```

### Шаг 4: Создать изображения для виджета

Создайте папку `widget/images/` и добавьте:

1. **logo.png** - Логотип виджета (рекомендуемый размер: 200x200px)
2. **icon.png** - Иконка для списка виджетов (рекомендуемый размер: 64x64px)

**Пример структуры:**
```
widget/
├── manifest.json
├── script.js
├── styles.css
├── demo.html
├── i18n/
│   ├── ru.json
│   └── en.json
└── images/
    ├── logo.png    ← ДОБАВИТЬ
    └── icon.png    ← ДОБАВИТЬ
```

### Шаг 5: Создать ZIP архив

Создайте ZIP архив со следующей структурой:

```
timesheet_il_widget.zip
├── manifest.json
├── script.js
├── styles.css
├── i18n/
│   ├── ru.json
│   └── en.json
└── images/
    ├── logo.png
    └── icon.png
```

**⚠️ ВАЖНО:**
- Все файлы должны быть в корне архива (не в подпапке!)
- Не включайте `demo.html` в архив

**Команда для создания архива (Windows PowerShell):**
```powershell
cd widget
Compress-Archive -Path manifest.json,script.js,styles.css,i18n,images -DestinationPath ..\timesheet_il_widget.zip
```

## 🚀 УСТАНОВКА В amoCRM

### Шаг 1: Войти в amoCRM

1. Откройте ваш аккаунт amoCRM
2. Перейдите в **Настройки** (иконка шестерёнки в правом верхнем углу)

### Шаг 2: Перейти в раздел виджетов

1. В меню настроек выберите **Интеграции**
2. Выберите **Виджеты**
3. Нажмите **"Добавить виджет"** или **"Загрузить свой виджет"**

### Шаг 3: Загрузить ZIP архив

1. Выберите файл `timesheet_il_widget.zip`
2. Нажмите **"Загрузить"**
3. Дождитесь проверки виджета системой amoCRM

### Шаг 4: Настроить виджет

После загрузки появится страница настроек виджета:

1. **Включить виджет** - переключите тумблер в положение "Вкл"
2. **API Settings** (если требуется):
   - Введите настройки подключения к вашему backend
   - Сохраните настройки
3. Нажмите **"Сохранить"**

### Шаг 5: Выбрать разделы для отображения

Виджет настроен для отображения в следующих разделах (см. `manifest.json`):

- ✅ **lcard-1** - Карточка лида (основная вкладка)
- ✅ **lcard-2** - Карточка лида (дополнительная вкладка)
- ✅ **ccard** - Карточка контакта
- ✅ **comcard** - Карточка компании
- ✅ **tcard** - Карточка задачи
- ✅ **settings** - Настройки

Выберите нужные разделы и сохраните.

## ⚙️ НАСТРОЙКА BACKEND API

### Шаг 1: Проверить, что backend запущен

```bash
# Проверить статус Docker контейнеров
docker-compose ps

# Должны быть запущены:
# - backend (FastAPI)
# - db (PostgreSQL)
```

### Шаг 2: Настроить CORS

Убедитесь, что в `backend/app/main.py` настроен CORS для amoCRM:

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "https://*.amocrm.ru",      # ← Важно для amoCRM
        "https://*.amocrm.com",
        "http://localhost:3000",
        "*"  # ← Только для разработки! Убрать в production
    ],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

### Шаг 3: Сделать API публичным

Для тестирования виджета API должен быть доступен из интернета.

**Вариант 1: Production сервер**
```bash
# Разместите backend на сервере с доменом
https://api.your-company.com
```

**Вариант 2: ngrok (для локальной разработки)**
```bash
# Установить ngrok: https://ngrok.com/download
# Запустить туннель
ngrok http 8000

# Получите публичный URL:
# https://abc123.ngrok.io
```

### Шаг 4: Проверить доступность API

Откройте в браузере:
```
https://your-api-url.com/docs
```

Должна открыться Swagger документация FastAPI.

## 🐛 ПРОБЛЕМЫ И РЕШЕНИЯ

### Проблема 1: Виджет не загружается

**Симптомы:**
- Виджет не отображается в карточках
- В консоли ошибка: "Failed to load resource"

**Решение:**
1. Проверьте, что виджет включен в настройках amoCRM
2. Проверьте структуру ZIP архива (файлы должны быть в корне)
3. Очистите кэш браузера (Ctrl+Shift+Delete)
4. Проверьте консоль на наличие JavaScript ошибок

### Проблема 2: Ошибка "CORS policy"

**Симптомы:**
```
Access to XMLHttpRequest at 'http://localhost:8000/api/...' 
from origin 'https://yoursubdomain.amocrm.ru' has been blocked by CORS policy
```

**Решение:**
1. Обновите настройки CORS в `backend/app/main.py`:
```python
allow_origins=[
    "https://*.amocrm.ru",
    "https://*.amocrm.com",
]
```
2. Перезапустите backend:
```bash
docker-compose restart backend
```

### Проблема 3: API недоступен (ERR_CONNECTION_REFUSED)

**Симптомы:**
- В консоли: "Failed to connect to API"
- Ошибка: "ERR_CONNECTION_REFUSED"

**Решение:**
1. Убедитесь, что backend запущен:
```bash
docker-compose ps
curl http://localhost:8000/docs
```

2. Если используете ngrok, обновите URL в `widget/script.js`

3. Проверьте firewall/security groups (должен быть открыт порт 8000 или 443)

### Проблема 4: Виджет работает, но данные не сохраняются

**Симптомы:**
- Кнопки нажимаются, но статус не меняется
- В консоли HTTP 500 или 404 ошибки

**Решение:**
1. Проверьте логи backend:
```bash
docker-compose logs backend --tail=50
```

2. Проверьте миграции БД:
```bash
docker-compose exec backend alembic current
docker-compose exec backend alembic upgrade head
```

3. Проверьте подключение к БД:
```bash
docker-compose exec backend python -c "from app.core.database import engine; print(engine.connect())"
```

### Проблема 5: CSS не применяется

**Симптомы:**
- Виджет отображается, но без стилей
- Кнопки выглядят как обычный HTML

**Решение:**
1. Убедитесь, что `styles.css` доступен по URL (строка 145 в `script.js`)
2. Проверьте в Network tab браузера, загружается ли CSS файл
3. Если используете CDN, убедитесь в правильности URL
4. Альтернатива: встройте CSS напрямую в `script.js`
