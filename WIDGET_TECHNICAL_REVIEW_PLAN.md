## 🔍 ПЛАН ПРОВЕРКИ ПО КАТЕГОРИЯМ

### 1. MANIFEST.JSON - Конфигурация виджета

#### ✅ Что проверено и найдено корректным:
- Версия указана: 3.0.2
- Interface version: 2 (актуальная версия)
- Локали: ru, en (корректно)
- Расположение: advancedSettings (настройки аккаунта)
- Поддержка и установка включены

#### ⚠️ Проблемы найдены:

**КРИТИЧНО:**
1. **Отсутствует секция `scopes`** - не указаны необходимые права доступа
   - Виджет использует `AMOCRM.constant('user')` и `AMOCRM.constant('account')`
   - Требуются права: `["crm"]` минимум

2. **Некорректная локализация названия**
   - `"name": "widget.name"` - это ключ локализации, но может не работать в manifest
   - Рекомендуется: прямое указание или структура `{"ru": "...", "en": "..."}`

3. **Настройка api_url как optional (required: false)**
   - Код требует api_url (строка 34-40 script.js показывает alert)
   - Несоответствие: должно быть `"required": true`

**СРЕДНЕ:**
4. **Отсутствует секция `oauth`** - если требуется авторизация на внешнем сервере
5. **Туристические изображения** - путь `/images/tour_ru.png` не проверен на существование
6. **Пример URL в support** - `https://example.com/support` - замените на реальный

### 2. SCRIPT.JS - Логика виджета

#### ✅ Что работает корректно:
- AMD модульная структура (define)
- Отложенная загрузка jQuery
- Graceful degradation при недоступности backend
- Fallback на demo-данные при ошибке получения user info
- Таймер обновления интерфейса
- Lifecycle методы (init, destroy, etc.)

#### ⚠️ КРИТИЧЕСКИЕ проблемы:

**1. Обработка ошибок и пустых данных:**

**Строка 33-41:** API URL проверка блокирует инициализацию
```javascript
if (settings && settings.api_url) {
    widget.API_URL = settings.api_url;
} else {
    alert('Please configure API URL in widget settings');
    return false; // БЛОКИРУЕТ весь виджет!
}
```
- **Проблема:** `return false` из `init()` может вызвать сбой amoCRM
- **Решение:** Продолжить работу с предупреждением, но не блокировать инициализацию

**Строка 52:** Проверка response без валидации структуры
```javascript
if (response && response.session_id && response.status !== 'finished') {
```
- **Проблема:** Нет проверки типов данных, возможны ошибки при невалидном JSON
- **Нужно добавить:** Валидацию типов и защиту от некорректных данных

**Строка 100-112:** Дублирование кода getCurrentUser
- Метод `getCurrentUser()` не используется, но повторяет логику из `init()`
- Мёртвый код - удалить или использовать

**Строка 115-142:** Дублирование loadCurrentSession
- Метод `loadCurrentSession()` не используется, дублирует код из `init()`
- Мёртвый код - удалить или рефакторить

**2. Проблемы маршрутизации данных:**

**Строки 44-71:** AJAX запрос без timeout
```javascript
$.ajax({
    url: widget.API_URL + '/sessions/current',
    method: 'GET',
    // НЕТ: timeout, headers, правильной обработки статусов
```
- **Проблема:** Может зависнуть навсегда при медленном сервере
- **Решение:** Добавить `timeout: 10000` (10 сек)

**Строки 534-560:** POST без проверки Content-Type сервера
- Отправляется JSON, но нет проверки что сервер понял формат
- Добавить проверку xhr.status и responseJSON

**3. Проблемы с правами доступа:**

**Строки 20-30:** Доступ к AMOCRM.constant без проверки прав
```javascript
widget.accountId = AMOCRM.constant('account').id;
widget.userId = AMOCRM.constant('user').id;
```
- **Проблема:** Если нет прав `scopes` в manifest, вызовет ошибку
- **Решение:** Обернуть в try-catch (уже есть, но нужна проверка scopes в manifest!)

**4. JavaScript ошибки:**

**Строка 471:** Неправильная версия в консоли
```javascript
console.log('Overlay v3.0.1 created');
```
- Должно быть: `v3.0.2` (согласно manifest)

**Строка 647-654:** padStart может не работать в старых браузерах
```javascript
return String(hours).padStart(2, '0') + ':' + ...
```
- **Проблема:** IE11 и старые Edge не поддерживают padStart
- **Решение:** Добавить polyfill или свою функцию

**Строка 152-196:** Inline HTML в коде (плохая практика)
```javascript
var overlayHTML = `
    <!-- огромная куча HTML -->
`;
```
- **Проблема:** Сложно поддерживать, нет минификации
- **Рекомендация:** Вынести в templates или использовать сборщик

**Строка 199-459:** Inline CSS в JavaScript (260 строк!)
```javascript
var css = `<style>...</style>`;
$('head').append(css);
```
- **Проблема:** Дублирование с styles.css, конфликты стилей
- **Решение:** Использовать только styles.css или модульные стили

**5. Обработка пустых данных:**

**Строка 509-528:** updateOverlayState не проверяет существование элементов
```javascript
$('#compact-timer').text(...);  // Может не существовать!
```
- **Проблема:** Если DOM не создан, вызовет ошибку
- **Решение:** Проверять существование перед обновлением

**Строка 627-637:** Таймер работает даже если нет сессии
```javascript
setInterval(function() {
    if (self.currentSession && self.sessionStart) {
        // обновление
    }
}, 1000);
```
- **Проблема:** Интервал висит даже когда ничего не нужно обновлять
- **Рекомендация:** Останавливать интервал при отсутствии сессии

### 3. STYLES.CSS - Стили

#### ✅ Что корректно:
- Адаптивность (@media queries)
- Анимации (плавные transitions)
- Хорошая типографика
- Состояния кнопок (hover, disabled)

#### ⚠️ Проблемы:

**СРЕДНЕ:**
1. **НЕ ИСПОЛЬЗУЕТСЯ в script.js!**
   - script.js создаёт свои inline стили (строка 199-459)
   - styles.css содержит классы типа `.timesheet-widget`, но они не применяются
   - **Конфликт архитектуры:** Два источника стилей

2. **z-index конфликты:**
   - В script.js: `z-index: 999999` и `z-index: 1000000`
   - В styles.css: нет таких высоких z-index
   - **Проблема:** Может перекрыть модальные окна amoCRM

3. **Отсутствует namespace для классов:**
   - Классы типа `.loading`, `.timer` - слишком общие
   - Могут конфликтовать с amoCRM стилями
   - **Решение:** Добавить префикс `.tabel-il-*`
