## 🎯 ЧТО У ВАС ЕСТЬ СЕЙЧАС

У вас есть **ГОТОВАЯ СИСТЕМА** из двух частей:

### 1️⃣ **BACKEND (Ваш собственный сервер)** 🖥️
Это ваша "база данных с мозгами" - программа на Python, которая:
- **Хранит все данные** (кто, когда работал, сколько времени)
- **Обрабатывает запросы** (начать смену, сделать перерыв и т.д.)
- **Считает статистику** (отчёты, время работы)
- **Живёт на ВАШЕМ сервере** - вы полностью контролируете данные

**Технологии:**
- Python + FastAPI (быстрый веб-сервер)
- PostgreSQL (надёжная база данных)
- Docker (для лёгкого запуска)

### 2️⃣ **WIDGET (Виджет в amoCRM)** 📱
Это "красивая кнопочка" внутри amoCRM, которая:
- **Показывается** в карточках клиентов/сделок/задач
- **Отправляет запросы** на ваш backend
- **Отображает информацию** сотруднику (таймер, кнопки)
- **Живёт внутри amoCRM** - загружается как дополнение

**Технологии:**
- JavaScript (код виджета)
- HTML/CSS (внешний вид)

## 🔄 КАК ЭТО РАБОТАЕТ (ПОШАГОВО)

### Пример: Сотрудник начинает рабочий день

```
1. Сотрудник открывает карточку клиента в amoCRM
   └─> amoCRM показывает ваш виджет на боковой панели

2. Виджет загружается в браузере сотрудника
   └─> Виджет видит: "Нет активной смены"
   └─> Показывает кнопку "▶️ Начать рабочий день"

3. Сотрудник нажимает кнопку
   └─> Виджет отправляет запрос на ВАШ сервер:
       POST https://ваш-сервер.com/api/v1/sessions/start
       { user_id: 12345, name: "Иван Петров" }

4. Ваш backend получает запрос
   └─> Сохраняет в базу данных:
       - ID сотрудника
       - Время начала смены
       - Статус: "работает"

5. Backend отправляет ответ виджету
   └─> { status: "working", start_time: "2026-07-30 10:00:00" }

6. Виджет получает ответ
   └─> Показывает таймер: "00:00:01... 00:00:02..."
   └─> Меняет кнопки на "⏸️ Перерыв" и "⏹️ Завершить"

7. Всё время виджет "разговаривает" с ВАШИМ сервером
   └─> amoCRM только показывает виджет
   └─> Все данные хранятся У ВАС
```

## ✅ ЧТО ХОРОШО В ВАШЕЙ АРХИТЕКТУРЕ

### 1. **Полный контроль данных** 🔒
- Все данные хранятся на ВАШЕМ сервере
- amoCRM не имеет доступа к детальной информации
- Вы можете делать backup, экспортировать, анализировать

### 2. **Независимость от amoCRM** 🆓
- Если захотите, можно сделать веб-версию
- Можно интегрировать с другими CRM
- Можно использовать данные в других системах

### 3. **Гибкость** 🔧
- Можете менять логику на своём сервере
- Можете добавлять новые функции
- Можете настраивать под свои процессы

### 4. **Безопасность** 🛡️
- Виджет только "показывает" данные
- Все важные операции на вашем сервере
- Можете настроить доступы, шифрование

## 🔌 КАК ВИДЖЕТ ПОДКЛЮЧАЕТСЯ К amoCRM

### Что делает виджет С amoCRM:

1. **Получает информацию о сотруднике:**
   - ID пользователя
   - Имя
   - Email
   - Отдел

2. **Получает информацию о карточке:**
   - ID сделки/контакта/компании
   - Название
   - Тип (лид, контакт, компания)

3. **Отображается в карточках:**
   - Сбоку в карточке клиента
   - Сбоку в карточке сделки
   - Сбоку в карточке задачи

### Что виджет НЕ ДЕЛАЕТ с amoCRM:

❌ Не меняет данные в amoCRM (клиенты, сделки)  
❌ Не создаёт задачи автоматически  
❌ Не отправляет данные в amoCRM  

**ВАЖНО:** Виджет только "живёт" внутри интерфейса amoCRM, но работает полностью с ВАШИМ сервером!

## 🚀 ЧТО НУЖНО ДЛЯ PRODUCTION

### Для работы в реальных условиях нужно:

### 1. **Сервер для backend** (ваша программа)

**Варианты:**

#### Вариант А: Облачный сервер (рекомендуется)
- **Amazon AWS** (надёжно, дорого)
- **DigitalOcean** (средне, оптимально)
- **Yandex Cloud** (российский, удобно)
- **Timeweb** (российский, дёшево)

**Что нужно:**
- Сервер с Linux
- 2 GB RAM минимум
- 20 GB диск
- Постоянный IP адрес
- Доменное имя (например: api.ваша-компания.ru)

#### Вариант Б: Свой сервер в офисе
- Компьютер или сервер
- Постоянное подключение к интернету
- Белый IP адрес
- Настройка роутера (проброс портов)

### 2. **HTTPS сертификат** (обязательно!)

amoCRM требует безопасное подключение.

**Варианты:**
- Let's Encrypt (бесплатно, автоматически)
- Cloudflare (бесплатно + защита)
- Платный сертификат

### 3. **Настройка домена**

Нужен домен типа: `api.ваша-компания.ru`

**DNS записи:**
```
A-запись: api.ваша-компания.ru → IP вашего сервера
```

### 4. **Установка на сервер**

```bash
# 1. Установить Docker
# 2. Скопировать ваш код на сервер
# 3. Настроить переменные окружения (.env)
# 4. Запустить:
docker-compose up -d

# 5. Применить миграции БД:
docker-compose exec backend alembic upgrade head
```

### 5. **Настройка виджета**

Пересобрать виджет с адресом вашего сервера:

```powershell
.\build_widget.ps1 -ApiUrl "https://api.ваша-компания.ru/api/v1"
```

Загрузить в amoCRM.

## 🎯 ПРОСТЫМИ СЛОВАМИ

### Аналогия:

Представьте, что:
- **amoCRM** - это торговый центр
- **Виджет** - это ваш магазин в этом центре (вывеска, витрина)
- **Backend** - это ваш склад и офис (где-то в другом месте)

**Когда клиент приходит в магазин:**
1. Видит вывеску (виджет загрузился)
2. Нажимает "купить" (кнопка в виджете)
3. Продавец звонит на склад (запрос к backend)
4. Склад проверяет наличие (проверка в БД)
5. Склад подтверждает (ответ от backend)
6. Продавец говорит "ОК" (виджет показывает результат)

**Важно:**
- Торговый центр (amoCRM) не знает, что у вас на складе
- Склад (backend) полностью ваш, независимый
- Магазин (виджет) - просто посредник
