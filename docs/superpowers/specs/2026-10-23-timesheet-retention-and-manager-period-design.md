# Хранение табеля за год и период доступа руководителей — проект решения

## Цель

Отчётные данные табеля хранятся 365 календарных дней. Администратор видит весь доступный год. Для каждой группы учёта администратор назначает руководителя и допустимую глубину просмотра общего табеля.

## Правила доступа

- Администратор может просматривать и выгружать данные любой группы за любой период внутри последних 365 дней.
- В карточке группы рядом с полем «Руководитель» появляется поле «Период табеля для руководителя» в днях, от 1 до 365.
- Руководитель видит только назначенные ему группы, как и сейчас. Для выбранной группы он видит не больше настроенного количества последних календарных дней.
- Если руководитель открывает «Все группы», применяется самый короткий период среди назначенных ему групп. Это исключает случайную выдачу более старых данных одной из групп.
- Ограничение проверяет backend для экранного отчёта и Excel. Изменение дат в браузере не позволяет его обойти.
- Интерфейс получает разрешённую минимальную и максимальную дату, ограничивает поля выбора и показывает понятное сообщение при выходе за границы.

## Хранение

- Нормализованные данные смен, статусов, опозданий, активности, CRM-событий и звонков сохраняются 365 дней.
- Ежедневная фоновая очистка удаляет закрытые отчётные данные старше 365 дней ограниченными пакетами, чтобы не останавливать работу до 50 аккаунтов.
- Открытая смена никогда не удаляется независимо от даты начала.
- Настройки, пользователи, группы и OAuth-подключения не относятся к годовой очистке.
- Сырые технические события amoCRM продолжают храниться 30 дней: для отчётов используются нормализованные данные, а длительное хранение полных исходных payload увеличивает объём и риск хранения лишних персональных данных.

## Изменения данных и API

- В `widget_groups` добавляется `report_history_days` с ограничением `1..365` и значением по умолчанию `365`.
- Снимок настроек загружает и сохраняет это поле вместе с руководителем группы.
- Каталог сотрудников для отчёта возвращает границы доступного периода для текущей роли и групп.
- `GET /reports/detailed` и обе Excel-точки применяют одинаковую проверку периода.
- Фоновый worker получает отдельную пакетную очистку годовых отчётных данных с повторяемыми безопасными запусками.

## Проверка

Тесты должны подтвердить миграцию и значение по умолчанию, сохранение настройки, полный год администратора, разные периоды двух групп, самый короткий период для «Всех групп», запрет обхода через API и Excel, сохранение открытой смены, удаление старых связанных строк и пакетную очистку без смешивания аккаунтов.
