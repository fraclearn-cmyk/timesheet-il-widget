# Объяснительные при опоздании — технический проект

## Цель и границы

Виджет должен запрашивать у сотрудника объяснительную в двух случаях: при опоздании к началу рабочего дня и при превышении допустимой длительности перерыва. Администратор включает или отключает это требование отдельно для каждого сотрудника. Пока обязательная объяснительная не заполнена, сотрудник не может начать или продолжить работу.

Изменение охватывает настройки, рабочие команды сотрудника, хранение данных, экран табеля, Excel-выгрузку и разграничение прав. Существующие аккаунты после обновления продолжают работать как раньше: требование объяснительной по умолчанию выключено, а настраиваемая допустимая длительность одного перерыва первоначально равна 60 минутам.

## Правила расчёта

### Опоздание к началу дня

Сервер сравнивает момент выполнения команды «Начать рабочий день» с началом смены группы в её часовом поясе. Если команда выполнена позже начала смены, сервер рассчитывает целое число минут опоздания по действующему правилу табеля.

Если для сотрудника включена обязательная объяснительная, команда без непустого текста отклоняется. Рабочая смена при этом не создаётся. После ввода текста та же команда создаёт смену и запись об опоздании в одной транзакции.

### Опоздание с перерыва

В настройках каждой группы появляется редактируемое поле «Допустимая длительность одного перерыва, минут» со значением 60 по умолчанию. Администратор может установить для разных групп разные пределы. Новое значение применяется к следующим командам возврата с перерыва; уже сохранённые случаи опоздания не пересчитываются. Сервер сравнивает длительность текущего перерыва с действующим пределом его группы. Опозданием считается только превышение: например, при пределе 60 минут и перерыве 68 минут в отчёт попадает 8 минут.

Если объяснительная обязательна, команда «Продолжить работу» без текста отклоняется, а сотрудник остаётся на перерыве. После ввода текста сервер завершает перерыв и сохраняет отдельную запись об опоздании. Каждый поздний возврат сохраняется отдельно и получает порядковый номер перерыва в пределах смены.

### Округление и границы

- Ровно в момент начала смены опоздания нет.
- Перерыв, равный допустимому пределу, не считается опозданием.
- Неполная превышенная минута округляется вверх, чтобы интерфейс и отчёт не показывали ноль при фактическом опоздании.
- Текст после удаления пробелов в начале и конце должен содержать хотя бы один символ и не превышать 1000 символов.
- Время браузера не используется для принятия решения; расчёт выполняет сервер.

## Настройки администратора

В строке каждого пользователя появляется флаг `require_late_reason` с подписью «Объяснительная при опоздании». Один флаг действует и для начала дня, и для возврата с перерыва. Настройка хранится в членстве пользователя в группе, потому что параметры уже привязаны к конкретному аккаунту и группе.

В карточке каждой группы появляется редактируемое целое поле `break_limit_minutes` с подписью «Допустимый перерыв, минут». Допустимый диапазон — от 1 до 720 минут, первоначальное значение — 60 минут. Значение применяется ко всем сотрудникам этой группы. Для сотрудников с обязательной объяснительной превышение блокирует возврат до ввода причины; для остальных превышение только записывается в отчёт.

Менять эти параметры может только администратор аккаунта. Руководитель видит табель своей группы, но не получает административные настройки. Сотрудник не может изменить требование для себя.

## Хранение данных и миграция

Миграция `015` добавляет:

- `group_members.require_late_reason BOOLEAN NOT NULL DEFAULT FALSE`;
- `widget_groups.break_limit_minutes INTEGER NOT NULL DEFAULT 60` с ограничением диапазона;
- увеличение допустимой длины `work_sessions.late_reason` до 1000 символов для совместимости;
- таблицу `lateness_incidents` для отдельных случаев опоздания.

Запись `lateness_incidents` содержит:

- внутренний идентификатор;
- `account_id` для строгой изоляции аккаунтов;
- `work_session_id` и `amocrm_user_id`;
- вид события: `shift_start` или `break_return`;
- номер события: `0` для начала дня и порядковый номер перерыва для `break_return`;
- момент события в UTC;
- число минут опоздания;
- текст объяснительной;
- дату создания.

Уникальность события задаётся по смене, виду и порядковому номеру. Индексы поддерживают выборку по аккаунту, сотруднику, смене и рабочей дате. Запись о событии, смена или переход статуса, а также результат идемпотентной команды сохраняются одной транзакцией.

Существующие `work_sessions.late_minutes` и `work_sessions.late_reason` сохраняются на время совместимости. Новая запись начала дня заполняет их вместе со структурированной записью, а новые отчёты читают структурированные события. Старые смены без события отображаются через прежнее значение `late_minutes`, объяснительная для них остаётся пустой.

## API рабочего статуса и команд

Ответ `GET /api/v1/timesheet/my-status` дополняется полями:

- `late_reason_required` — требуется ли текст перед текущей доступной командой;
- `late_reason_kind` — `shift_start`, `break_return` или `null`;
- `late_minutes` — рассчитанное число минут;
- `break_sequence` — номер позднего перерыва или `null`.

Тело команд `start-work` и `end-break` принимает необязательное поле `reason`. Сервер повторно рассчитывает опоздание в момент команды. Если объяснительная обязательна и текст пуст, API возвращает `409` с устойчивым кодом `LATE_REASON_REQUIRED`, рассчитанными минутами и видом события. Состояние смены не меняется.

Ключ идемпотентности связывается с действием и нормализованным содержимым команды. Повтор полностью одинакового запроса возвращает сохранённый результат. Повтор ключа с другим действием или другим текстом возвращает конфликт и не создаёт вторую запись.

## Интерфейс сотрудника

При обязательной объяснительной рабочая панель показывает:

- понятное сообщение о виде и длительности опоздания;
- многострочное поле «Причина опоздания»;
- счётчик ограничения в 1000 символов;
- кнопку «Начать рабочий день» или «Продолжить работу».

Пока поле пустое после удаления пробелов, кнопка отключена и имеет серый цвет. После ввода текста кнопка становится активной и синей. Клиентская блокировка нужна для понятного поведения, но окончательное решение всегда принимает сервер.

Если время перешло границу уже после получения статуса, сервер возвращает `LATE_REASON_REQUIRED`. Виджет не теряет введённые данные, обновляет состояние и показывает поле объяснительной. При недоступности сервера действуют существующие правила безопасного интерфейса: виджет не изображает успешное начало или продолжение работы.

## Табель и отчёт

Старая одиночная колонка «Опоздание» заменяется блоком из четырёх колонок в конце таблицы:

| Уровень 1 | Уровень 2 | Уровень 3 |
| --- | --- | --- |
| Опоздания | Начало дня | Минуты |
| Опоздания | Начало дня | Объяснительная |
| Опоздания | Перерыв | Минуты |
| Опоздания | Перерыв | Объяснительная |

Для начала дня показывается одно значение минут и один текст. Для перерывов в колонке минут показывается сумма превышений за смену. В колонке объяснительных показывается нумерованный список всех поздних возвратов, например:

`Перерыв №1 — 8 мин: задержался на встрече; Перерыв №2 — 5 мин: проблема со связью`.

API отчёта возвращает отдельные безопасные поля для минут начала дня, его объяснительной, суммы минут по перерывам и массива объяснений по поздним перерывам. Интерфейс вставляет тексты как текстовые узлы, без выполнения HTML.

В выборе колонок и Excel-выгрузке доступны четыре независимых поля. Ранее сохранённое значение `lateness` автоматически трактуется как «Начало дня — минуты», поэтому пользовательские настройки после обновления не сбрасываются. Значения по умолчанию для новой установки включают все четыре поля.

## Excel-выгрузка

Excel повторяет структуру экранного отчёта тремя строками заголовка. Ячейка «Опоздания» объединяет четыре колонки, «Начало дня» и «Перерыв» объединяют по две. Объяснения отдельных перерывов выводятся с новой строки и с переносом текста.

Перед записью пользовательский текст обезвреживается от формул Excel: значения, начинающиеся с `=`, `+`, `-` или `@`, сохраняются как обычный текст. Это же правило применяется ко всем новым текстовым полям выгрузки.

## Права и изоляция

- Сотрудник передаёт объяснительную только для собственной текущей смены.
- Руководитель видит данные только сотрудников назначенной ему группы.
- Администратор видит отчёты аккаунта и управляет настройками.
- Каждый запрос и каждая запись ограничены подтверждённым `account_id`; идентификаторы из браузера не являются основанием для доступа.
- Выборки рассчитаны на 40 аккаунтов amoCRM и не выполняют отдельный запрос на каждую строку отчёта.

## Проверка

Реализация должна покрыть следующие сценарии:

- миграция на пустой и заполненной базе, значения по умолчанию и откат;
- сохранение настроек группы и сотрудника, проверка ролей и изоляции аккаунтов;
- начало дня вовремя, поздно с выключенным требованием, поздно с пустым, пробельным и заполненным текстом;
- возврат вовремя, ровно на границе, после границы и несколько поздних перерывов за смену;
- конкурентные и повторные команды с одинаковыми и различающимися ключами;
- отключённая серая и активная синяя кнопка для обеих команд;
- восстановление интерфейса после серверного ответа `LATE_REASON_REQUIRED`;
- четыре колонки отчёта, нумерация нескольких перерывов и разграничение ролей;
- трёхуровневые объединённые заголовки Excel, переносы строк и защита от формул;
- регрессия для 40 аккаунтов, сборка пакета и точный состав ZIP.
