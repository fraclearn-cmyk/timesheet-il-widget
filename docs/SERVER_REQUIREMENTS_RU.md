# Требования к серверу для виджетов amoCRM

Актуальность исследования: 15 октября 2026 года.

## Рекомендация

Для текущего виджета «Табель IL» и следующих виджетов этой же компании рекомендуется один масштабируемый облачный VPS в российском дата-центре. Стартовая конфигурация рассчитана на 50 аккаунтов amoCRM и несколько дополнительных виджетов умеренной нагрузки.

### Конфигурация для покупки

| Параметр | Рекомендуемое значение |
|---|---|
| Тип услуги | Облачный VPS/VDS с возможностью увеличения ресурсов |
| Размещение | Российская Федерация, предпочтительно Москва |
| Операционная система | Ubuntu Server 24.04 LTS x64 |
| Процессор | 4 vCPU |
| Оперативная память | 8 ГБ RAM |
| Диск | 100–120 ГБ NVMe SSD |
| Сеть | Не менее 100 Мбит/с, без жёсткого ограничения трафика |
| IP-адрес | Один постоянный публичный IPv4 |
| Резервное копирование | Ежедневные копии БД и еженедельный снимок сервера |
| Доступ | SSH по ключам, консоль восстановления, двухфакторная защита кабинета |
| ПО | Docker Engine, Docker Compose, Nginx или Caddy, PostgreSQL 15+, мониторинг |

Панель ispmanager для проекта не требуется. Она увеличивает стоимость и потребление памяти, а развёртывание виджетов выполняется через Docker.

### Допустимые варианты

| Вариант | Ресурсы | Когда подходит |
|---|---|---|
| Минимальный пилот | 2 vCPU, 4 ГБ RAM, 60 ГБ NVMe | Только текущий виджет и короткая проверка; запас небольшой |
| Рекомендуемый старт | 4 vCPU, 8 ГБ RAM, 100–120 ГБ NVMe | Текущий табель, 50 аккаунтов и несколько следующих виджетов |
| Следующий уровень | 8 vCPU, 16 ГБ RAM, 200 ГБ NVMe | Несколько нагруженных виджетов или заметный рост объёма событий |

Увеличивать сервер следует после измерения реальной нагрузки. Ориентиры для перехода на следующий уровень: RAM постоянно выше 75%, CPU выше 70% в течение 15 минут, диск заполнен более чем на 70%, резервные копии или отчёты начинают заметно замедлять API.

## Как разместить несколько виджетов на одном сервере

1. На сервере работает один входной прокси Nginx или Caddy и принимает HTTPS-запросы.
2. Для каждого виджета создаётся отдельный поддомен, например `timesheet-api.company.ru` и `widget2-api.company.ru`.
3. Каждый виджет запускается как отдельный Docker Compose project со своей сетью, контейнером приложения, переменными окружения и журналами.
4. На старте можно использовать один PostgreSQL-сервер, но каждому виджету назначаются отдельные база данных и пользователь. Общие таблицы и общие пароли запрещены.
5. OAuth-ключи, токены amoCRM и ключи подписи у каждого виджета отдельные. Они хранятся только на сервере и не попадают в Git.
6. Мониторинг, HTTPS, firewall и резервное копирование используются совместно.
7. При росте PostgreSQL переносится на отдельную VM или управляемую БД без изменения публичных адресов виджетов.

Такое разделение позволяет обновить или перезапустить один виджет, не останавливая остальные. Один сервер всё равно остаётся общей точкой отказа, поэтому база и резервные копии должны храниться так, чтобы сервер можно было восстановить.

## Резервные копии

- Каждую ночь выполнять `pg_dump` каждой базы.
- Хранить минимум 7 ежедневных, 4 еженедельных и 6 ежемесячных копий.
- Копии отправлять в отдельное объектное хранилище, расположенное в РФ. Копия только на том же VPS не защищает от удаления или поломки сервера.
- Перед обновлением создавать снимок VPS.
- Не реже одного раза в три месяца проверять восстановление на временной базе.

## REG.RU / Рег.облако

REG.RU предлагает облачные VPS и выделенные серверы. Для этого проекта нужен облачный VPS: его проще увеличить без покупки физического сервера. У REG.RU есть площадки в Москве; при заказе нужно проверить, что выбранная локация прямо указана как российская.

Конфигуратор повторно проверен в авторизованном кабинете 20 октября 2026 года. Ближайший готовый тариф к требованию проекта — `HP C8-M8-D120`: 8 vCPU, 8 ГБ RAM и 120 ГБ NVMe за 5 006,05 ₽/мес. Он имеет запас по CPU для 50 аккаунтов и следующих виджетов. Публичный плавающий IPv4 стоит 187,38 ₽/мес.; минимальная фиксированная сумма без фактически занятого места резервных копий — 5 193,43 ₽/мес.

Резервное копирование оплачивается по фактически занятому объёму: до 5,26 ₽/мес. за 1 ГБ. Один полный объём 120 ГБ соответствует максимум 631,20 ₽/мес., но итог зависит от числа сохранённых копий и фактического объёма. Для согласования с клиентом разумно заложить 5 200–6 500 ₽/мес. и отдельно контролировать рост backup storage.

## Как оформить сервер через вашу реферальную ссылку

Для этой ситуации лучше бонусная реферальная программа, а не реселлерская партнёрская программа. Сервер, домены и оплата остаются в кабинете компании, а REG.RU обслуживает клиента напрямую.

1. Собственный кабинет REG.RU и «Бонусная программа» уже активны.
2. Отдельная ссылка «Сервер Табель IL — 50 аккаунтов» создана 20 октября 2026 года. Полный адрес хранится только в личном кабинете и передаётся клиенту напрямую; в публичный Git-репозиторий код ссылки не добавляется.
3. До покупки написать в поддержку REG.RU: «У клиента уже есть аккаунт REG.RU с доменами. Будет ли новый облачный VPS, заказанный и оплаченный из этого аккаунта после перехода по моей реферальной ссылке, считаться реферальной услугой?»
4. Сохранить ответ поддержки. Публичная инструкция не даёт однозначной гарантии для уже существующего аккаунта.
5. После подтверждения отправить клиенту реферальную ссылку. Для облачных услуг REG.RU разрешает привлечение через реферальную ссылку или реферальный сайт.
6. Клиент переходит по ссылке, входит в свой действующий кабинет и заказывает сервер в течение 14 календарных дней.
7. До оплаты проверить российскую локацию, итоговую цену, IPv4 и резервное копирование.
8. Клиент оплачивает сервер со своего расчётного счёта или карты. Владельцем услуги остаётся компания.
9. Вы получаете только технический доступ: отдельного пользователя с `sudo` и доступ по вашему SSH-ключу. Основной пароль кабинета и платёжные данные клиент не передаёт.
10. После начала использования проверить услугу в статистике бонусной программы.

По опубликованным условиям вознаграждение за VPS и облачные серверы составляет до 15% от фактически потраченных розничным рефералом средств. Для облачных услуг начисление выполняется за предыдущий месяц. Если заказ или оплата сделаны позже 14 дней после перехода, вознаграждение не начисляется. Если за 12 месяцев не привлечён новый реферал с новой услугой, REG.RU может остановить начисления и отменить текущие привязки.

Полноценная партнёрская/реселлерская программа нужна только тогда, когда вы хотите сами продавать услуги, назначать цену и принимать оплату клиента. Для сервера, который должен принадлежать компании, этот вариант сложнее и создаёт лишнюю зависимость от вашего кабинета.

## Домен компании

Переносить существующий домен не нужно. В кабинете REG.RU клиент создаёт отдельный поддомен и направляет его A-запись на IPv4 сервера. Рекомендуемая схема:

- `timesheet-api.company.ru` — текущий табель;
- `widget2-api.company.ru` — следующий виджет;
- `status-widgets.company.ru` — закрытая страница состояния, если она понадобится.

После настройки DNS на сервере выпускается бесплатный TLS-сертификат Let's Encrypt. Каждый виджет получает свой постоянный HTTPS URL, который сохраняется в настройках интеграции amoCRM.

## Порядок действий

1. Получить у REG.RU письменное подтверждение реферального начисления для существующего аккаунта клиента.
2. Согласовать с компанией бюджет и рекомендуемую конфигурацию `4/8/100`.
3. Клиент заказывает сервер в российской локации через вашу ссылку и оплачивает его из своего кабинета.
4. Клиент создаёт поддомен для табеля и выдаёт вам SSH-доступ по ключу.
5. Настроить Ubuntu, обновления безопасности, firewall, Docker, HTTPS и защиту SSH.
6. Развернуть PostgreSQL и текущий виджет через Docker Compose.
7. Настроить внешние резервные копии, мониторинг доступности и предупреждения о заполнении диска.
8. Перенести URL API виджета с временного туннеля на постоянный домен.
9. Выполнить проверку администратора, руководителя, сотрудника, отчёта, Excel и фонового сбора активности.
10. Каждый следующий виджет размещать в отдельном Docker Compose project и на отдельном поддомене.
11. Через месяц собрать показатели CPU, RAM, диска и базы и решить, оставлять конфигурацию или увеличивать её.

## Организационные и правовые условия

Табель хранит сведения о сотрудниках и их активности. Российский сервер помогает выполнить требование локализации, но сам по себе не закрывает все обязанности по Федеральному закону № 152-ФЗ. Компания должна определить владельца данных, основания обработки, сроки хранения, круг допущенных лиц и порядок удаления. До рабочего запуска рекомендуется проверить документы компании со специалистом по персональным данным.

Официальная справка: [Роскомнадзор — требования к операторам персональных данных](https://82.rkn.gov.ru/directions/pers/p15375/).
