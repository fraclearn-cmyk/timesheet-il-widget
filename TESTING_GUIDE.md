# 📋 Полное руководство по тестированию Timesheet IL Widget

## 🎯 Цель тестирования
Убедиться, что все функции виджета работают корректно и интегрируются с amoCRM.

---

## 📦 Что нужно для установки в amoCRM

### 1. Необходимые данные из amoCRM:

Для подключения виджета к amoCRM вам нужны:

- **Client ID** - ID вашего приложения в amoCRM
- **Client Secret** - Секретный ключ приложения  
- **Account ID** - ID вашего аккаунта amoCRM
- **Redirect URI** - URL для OAuth (например: `https://yourdomain.com/oauth/callback`)

### 2. Где взять эти данные:

1. Зайдите в amoCRM → Настройки → API
2. Создайте интеграцию (или используйте существующую)
3. Скопируйте Client ID и Client Secret
4. Установите Redirect URI

### 3. Обновите файл `.env`:

```env
AMOCRM_CLIENT_ID=ваш_client_id
AMOCRM_CLIENT_SECRET=ваш_client_secret
AMOCRM_REDIRECT_URI=https://yourdomain.com/oauth/callback
```

## 🚀 Процесс установки виджета в amoCRM

### Шаг 1: Подготовка файлов виджета

Виджет находится в папке `widget/`:
- `manifest.json` - манифест виджета
- `script.js` - основной код виджета
- `styles.css` - стили
- `i18n/ru.json` - русская локализация
- `i18n/en.json` - английская локализация

### Шаг 2: Загрузка в amoCRM

1. Зайдите в amoCRM → Настройки → Виджеты
2. Нажмите "Создать виджет"
3. Загрузите файлы из папки `widget/`
4. Активируйте виджет

### Шаг 3: Настройка виджета

После установки в настройках виджета укажите:
- **Backend URL**: `http://localhost:8000` (для тестирования) или ваш production URL
- **Account ID**: ID вашего аккаунта amoCRM

## ✅ Чек-лист тестирования

### 1️⃣ Проверка Backend API (локально)

Откройте: `d:\виджеты\timesheet-il-widget\frontend\index.html`

**Тестируйте последовательно:**

#### A. Рабочие сессии
- [ ] **Начать смену** - должна создаться новая сессия
- [ ] **Начать перерыв** - статус сессии меняется на "break"
- [ ] **Закончить перерыв** - возврат к активной работе
- [ ] **Завершить смену** - сессия завершается
- [ ] **Текущая сессия** - показывает активную сессию

**Обратите внимание:**
- Время начала и окончания записывается правильно
- Нельзя начать две смены одновременно для одного пользователя
- Перерыв можно начать только в активной сессии

#### B. Категории активностей
- [ ] **Создать категорию** - например "Обработка лидов", "Звонки клиентам"
- [ ] **Получить список** - все категории отображаются
- [ ] Цвет категории корректно сохраняется

**Обратите внимание:**
- Названия категорий уникальны в рамках аккаунта
- Цвета помогают визуально различать активности

#### C. Активности
- [ ] **Начать активность** - выбрать тип сущности (lead, contact, company)
- [ ] **Пауза** - приостановить активность
- [ ] **Продолжить** - возобновить после паузы
- [ ] **Остановить** - завершить активность

**Обратите внимание:**
- Активность привязывается к конкретной сущности amoCRM
- Время активности учитывается в статистике
- Можно отслеживать, сколько времени тратится на каждую сделку

#### D. Команда
- [ ] **Статистика команды** - общее время работы, перерывов
- [ ] **Активность команды** - кто чем занимается

**Обратите внимание:**
- Данные обновляются в реальном времени
- Можно фильтровать по дате

#### E. Отчёты
- [ ] **Генерировать отчёт** - за выбранный период
- [ ] **Список отчётов** - все созданные отчёты

**Обратите внимание:**
- Отчёты включают время работы, перерывов, по категориям
- Можно экспортировать данные

#### F. Настройки
- [ ] **Получить настройки** - текущие настройки аккаунта
- [ ] **Обновить настройки** - изменить параметры

**Обратите внимание:**
- Рабочие часы (начало/конец дня)
- Автоматические перерывы
- Таймаут неактивности

## 🐛 Частые проблемы и решения

### Проблема 1: API недоступен
**Симптом:** В интерфейсе показывается "API оффлайн"  
**Решение:** 
```bash
docker compose ps
# Проверьте, что контейнеры запущены
docker compose logs backend
# Посмотрите логи на наличие ошибок
```

### Проблема 2: Не создаётся сессия
**Симптом:** Ошибка при нажатии "Начать смену"  
**Решение:**
- Проверьте, что user_id существует
- Убедитесь, что нет активной сессии

### Проблема 3: CORS ошибки в браузере
**Симптом:** `Access-Control-Allow-Origin` ошибка  
**Решение:** Добавьте в backend/app/main.py:
```python
from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"],  # В production указать конкретные домены
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

### Проблема 4: Виджет не отображается в amoCRM
**Решение:**
1. Проверьте manifest.json на валидность
2. Убедитесь, что все файлы загружены
3. Проверьте настройки виджета в amoCRM
